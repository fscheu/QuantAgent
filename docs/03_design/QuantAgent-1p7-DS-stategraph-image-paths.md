# QuantAgent-1p7 — Design — StateGraph Image Paths

## Current State
- `SetGraph.set_graph()` builds and compiles the LangGraph topology.
- Repo-level docs already prefer `path-only` artifacts for charts and checkpoint-adjacent data.
- There is no documented per-change contract for persisting the compiled StateGraph visualization to disk.

## Gap
The issue asks for generated StateGraph images to be shareable/debuggable outside runtime. That requires moving from transient in-memory image payloads to a disk artifact plus a propagated path reference.

## Proposed Change

### 1. Keep graph construction pure
`quantagent/graph_setup.py` should remain focused on building/compiling the graph. The image-export I/O should live in the orchestration layer that already owns runtime concerns.

### 2. Export after compile
`quantagent/trading_graph.py` should own a small helper that:
- obtains the compiled graph visualization from the already-built graph object;
- writes the generated bytes to a `.png` file under the local artifact tree;
- returns the resulting path string.

This keeps topology assembly separate from filesystem concerns.

### 3. Reuse existing artifact layout
Use the existing path-oriented convention documented in Streamlit MVP docs:
- root: `data/artifacts/`
- include contextual subfolders when available (`environment`, `run_or_thread`, `symbol`)
- include a deterministic filename suffix such as `stategraph.png`

If the exact runtime context is unavailable, the minimal fallback is still a file under `data/artifacts/` with a unique timestamped name.

### 4. Propagate path, never bytes
Any return structure, metadata blob, or UI-facing reference added by this ticket should expose:
- `stategraph_image_path: <string path>`

and should not expose:
- raw PNG bytes
- base64 image payloads
- large blobs embedded in checkpointed state

## Affected Components
- `quantagent/trading_graph.py` — runtime helper and reference propagation
- `quantagent/graph_setup.py` — only if a tiny non-I/O hook is required; otherwise unchanged
- Relevant consumer(s) of graph visualization metadata — update to read a file path string
- Tests covering export/reference behavior

## Technical Decisions
- **Decision:** keep local disk as the storage backend.
  - **Why:** aligns with current MVP/path-only policy and avoids unnecessary infrastructure.
- **Decision:** keep export logic near `TradingGraph`, not in `SetGraph`.
  - **Why:** avoids mixing graph topology assembly with artifact I/O.
- **Decision:** use path references in metadata instead of embedding blobs.
  - **Why:** prevents checkpoint/config payload bloat and matches existing docs.

## Verification Notes
- Unit test the exporter with a mocked graph visualization method that returns bytes.
- Verify the file is created under a temp artifact directory.
- Verify the stored/returned reference is a path string and does not contain base64/image bytes.
